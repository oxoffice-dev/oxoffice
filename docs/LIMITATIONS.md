# Known limitations

What this version of oxoffice cannot do yet, and what to do instead. Generated from
[`crates/oxoffice-cli/limitations.json`](../crates/oxoffice-cli/limitations.json) by
`scripts/limitations_doc.py`. The installed build gives the same list:

```bash
oxoffice limitations [docx|pptx] [--json]
python -c "import oxoffice; print(oxoffice.limitations('docx'))"
```

## docx

| Area | Limitation | Workaround | Issue |
| --- | --- | --- | --- |
| compare | Comparison refuses to insert or delete a paragraph holding a simple field: compare refuses with "cannot track a whole paragraph's simple field outside a field it replaces", so a heading added under a table of contents made by insert_toc cannot be compared | add or remove the paragraph by hand on the redline | [#66](https://github.com/oxoffice-dev/oxoffice/issues/66) |
| compare | Comparison refuses a paragraph moved after a final table, or added or deleted after a moved or redlined final table: compare refuses with "needs an adjacent paragraph for a final paragraph move" or "... for a final paragraph change" (after a table moved to the end), or "holds an existing tracked revision" (after a table that holds tracked changes) | put a paragraph after the table in both versions, or resolve the earlier tracked changes on both copies first | [#120](https://github.com/oxoffice-dev/oxoffice/issues/120) |
| replace | Text replacement through Python is slower than the CLI: about 1.5 times the time of the CLI for the same pairs | when only replacing, use `oxoffice docx replace FILE --map pairs.json` | [#5](https://github.com/oxoffice-dev/oxoffice/issues/5) |
| performance | Edits cost more as the document grows, most on files saved by Word or Google Docs: Run.text, Paragraph.text, add_run, Table.add_row, remove_content and notes cost the whole body: tens of milliseconds per call, up to seconds on long reports | batch the edits, or build the content aside and insert it once | [#6](https://github.com/oxoffice-dev/oxoffice/issues/6) |
| forms | Form operations cost seconds on long documents: about 0.1 s at 25 paragraphs, 3 to 9 s at 1,000 | pass every rule in one call | [#7](https://github.com/oxoffice-dev/oxoffice/issues/7) |
| text | Non-breaking hyphens and positional tabs are missing from paragraph text: Paragraph text and text search skip w:noBreakHyphen and w:ptab, so "co-op" written with a non-breaking hyphen reads "coop", a search for "co-op" finds nothing, and replacing "coop" leaves the hyphen after the replacement | search for the text on each side of the hyphen or positional tab | [#26](https://github.com/oxoffice-dev/oxoffice/issues/26) |
| styles | Word files saved in another language: new comments do not use the file's comment styles: a comment added to a Word file with localised style ids, such as Commentaire, gets new CommentText and CommentReference styles based on Normal, so it does not look like Word's comments | set the new comment's paragraphs and its reference mark to the file's comment styles, the styles named "annotation text" and "annotation reference" | [#27](https://github.com/oxoffice-dev/oxoffice/issues/27) |
| headers | Setting the document header or footer changes the last section only: set_header() and set_footer() give the last section its own header or footer, so the earlier sections it inherited from keep the old one | read and edit each section's header: Rust section_story(section, kind, variant), Python document.section(i).header | [#28](https://github.com/oxoffice-dev/oxoffice/issues/28) |
| notes | Removing a paragraph leaves its notes behind, and removing a note leaves its custom mark: remove_content keeps the paragraph's footnotes and endnotes as unreferenced notes; removing a note made with a custom mark (Rust create_footnote_with_mark) keeps the mark | remove the paragraph's notes first (remove_footnote, remove_endnote, same names in Python); delete a leftover mark with replace_text | [#30](https://github.com/oxoffice-dev/oxoffice/issues/30) |
| lists | A list item numbered through its style cannot be restarted: restart_numbering fails with "paragraph has no explicit numbering level" on the List Number paragraphs of Word and python-docx files, whose numbering comes from the style | Rust: give the paragraph its own numbering first (set_numbering with the num_id and level of effective_paragraph_properties), then restart; Python: start a new list (add_numbering_definition, add_numbering_instance, Paragraph.numbering) | [#82](https://github.com/oxoffice-dev/oxoffice/issues/82) |
| forms | Content control values keep the prompt's style, and text() glues a block control's paragraphs: a value set on a control showing its prompt stays greyed out in Word, a line feed shows as a space, extra paragraphs stay empty, a combo box refuses free text, and text() runs paragraphs together | read a block control's paragraphs one by one with story_paragraphs: they are the entries whose location path is [i, 0], [i, 1]..., i being the control's index in story_items (index_path in Python) | [#147](https://github.com/oxoffice-dev/oxoffice/issues/147) |
| forms | The tag setters do not reach content controls in headers: set_content_control_value_by_tag returns 0 for a control in a header and content_controls() lists body controls only; `oxoffice docx fill` fails with "no content control has tag" (--tag) or "requires exactly one target" (--values) | fill_form with a rule naming the tag (a content control tag target), which reaches every story (same name in Python); none through the CLI | [#148](https://github.com/oxoffice-dev/oxoffice/issues/148) |
| forms | A date content control in Word's long date format cannot be set: setting a control formatted d MMMM yyyy fails with "unsupported or missing date format", and protect_form refuses rules naming it | give the control a yyyy-MM-dd or dd/MM/yyyy date format first (set_content_control_type, same name in Python), then set the value; none through the CLI | [#149](https://github.com/oxoffice-dev/oxoffice/issues/149) |
| pdf | PDF pages: a blank page before a section break, endnotes over a final table, outline entries on the wrong page: a page break just before a next-page section break leaves a blank page; endnotes overlap a table that ends the document; an outline entry opens the page before a heading moved by keep with next | remove the page break before a next-page section break; end the document with a paragraph after a final table; put a page break before such a heading | [#156](https://github.com/oxoffice-dev/oxoffice/issues/156) |
| pdf | PDF text: right-to-left paragraphs start at the left margin, CJK text is drawn as boxes by default: a right-to-left paragraph is drawn against the left margin, and Chinese, Japanese and Korean glyphs are empty boxes with the default render options | none for right-to-left paragraphs (an explicit right alignment would move them left in Word and LibreOffice); for CJK, pass a CJK font file (Rust to_pdf_with_fonts, or to_pdfa_with_fonts_deterministic for PDF/A; Python to_pdf(fonts=...) or font_dir=...; CLI convert --font-dir) or turn system fonts on (Rust to_pdf_with_options with use_system_fonts, Python to_pdf(system_fonts=True), CLI convert --system-fonts); none for PDF/A in Python and the CLI | [#157](https://github.com/oxoffice-dev/oxoffice/issues/157) |
| pdf | PDF endnotes are numbered 1, 2, 3 instead of i, ii, iii: endnotes without a number format of their own are numbered in decimal in the PDF, where Word numbers them in lower roman | set the endnote policy's number format to lower roman (set_note_policy, same name in Python) before converting; none through the CLI | [#158](https://github.com/oxoffice-dev/oxoffice/issues/158) |
| compare | Comparison refuses an endnote added, removed or moved, or a change it writes as a deletion and an insertion around an endnote: compare refuses with "endnotes story shell count changed", "identical related-story shells" or "its reference moved to another site" (also when a table or paragraph holding an endnote is replaced whole), and with endnotes ignored "ignored endnotes cannot supply the edited reference to endnote N" when the edited version references an endnote the original does not hold | make the endnote change on the accepted result after comparing, or compare that pair in Word | [#68](https://github.com/oxoffice-dev/oxoffice/issues/68) |
| text | Word and character counts and the heading list leave out text inserted with tracked changes: word_count and character_count (Rust, Python, CLI info) and headings / document_outline (Rust) read a paragraph's direct runs, so a document edited with tracking on counts fewer words than text() holds | count the words of the accepted paragraph texts, and their characters paragraph by paragraph (text() adds a line feed after each paragraph and a tab between cells): Rust text(), Python the .text of doc.paragraphs and of table cell paragraphs, CLI paragraphs[].text of oxoffice docx text --json; read headings from numbered_document_outline (Rust) | [#184](https://github.com/oxoffice-dev/oxoffice/issues/184) |
| pictures | A floating picture added by add_anchored_image gets the alt text "Background": Rust add_anchored_image writes descr="Background" on every picture it adds, which Word shows and screen readers read aloud | Rust: add the picture with add_picture_with_options, anchor set and the description wanted; Python add_picture and the CLI do not take this path | [#185](https://github.com/oxoffice-dev/oxoffice/issues/185) |

## pptx

| Area | Limitation | Workaround | Issue |
| --- | --- | --- | --- |
| open | A presentation part with a control character is refused at open: open fails with "PackageError ... holds U+0001" and `oxoffice pptx validate` exits 1, while PowerPoint opens the file | remove the character from that part's bytes, then open the file | [#8](https://github.com/oxoffice-dev/oxoffice/issues/8) |
| slides | Importing slides with their source formatting refuses PowerPoint and Google slides that have notes: import_slides with keep_source_formatting fails with "unrepresentable source notes-master ... authority", calling the producer's part malformed | import onto this deck's layouts instead, without keeping the source formatting | [#40](https://github.com/oxoffice-dev/oxoffice/issues/40) |
| slides | Sections do not follow added, duplicated, imported or moved slides: a new slide belongs to no section, and a moved slide stays listed in its old section | set the sections again after the slide edits (set_sections in Rust and Python); none through the CLI | [#41](https://github.com/oxoffice-dev/oxoffice/issues/41) |
| tables | Google tables cannot lose columns down to one: remove_column fails with "table frame size must remain positive" | before removing columns, set the first column to its own width (Rust set_column_width, Python column.width) to resync the frame | [#44](https://github.com/oxoffice-dev/oxoffice/issues/44) |
| metadata | Document metadata goes stale after slides are added, duplicated, imported, retitled, hidden or edited: docProps/app.xml keeps its old slide, notes and hidden-slide counts and title lists (refreshed only on slide removal, and not when the source-preserving patch cannot edit app.xml, one outside its namespace for example), Words and Paragraphs are never recounted, core.xml keeps its title, and the package thumbnail keeps the first slide as it was saved | set the counts and the title through the document properties before saving (Rust set_application_properties and set_core_properties, Python prs.app_properties and prs.core_properties); for the title lists and the thumbnail, add a slide and remove it again, which drops both and recounts (Rust remove_application_properties also drops the title lists, with the rest of app.xml) | [#103](https://github.com/oxoffice-dev/oxoffice/issues/103) |
